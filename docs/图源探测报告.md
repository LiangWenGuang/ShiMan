`tools/probe-search2.mjs`（候选搜索地址矩阵），原始结果分别在

## 新接入的两个源

### 云北漫画（mhw1.com）

包子漫画的镜像站，同一个 CDN（`s1.bzcdn.net`）。

- 搜索 `/search?key={kw}`，条目 `.comic-list-item`
- 详情 `/index.php/comic/{slug}`，标题 `h1.comic-name`，封面在 `.box-back` 的
  `background-image` 里（用正则后处理抠出来），简介 `.comic-intro`
- 章节 `.catalog-list li.chapter-item a`，**倒序**，需 `reverse: true`
- 正文 `ul.comic-list li.comic-page img`，36 张

### 206漫画（m206.com）

## 探测过程中修掉的两个通用 bug

**1. `comicId` 抽取被域名数字污染。**
`extractNumericId` 原来取整串 URL 里第一段数字，而 206 的域名是 `m206.com`，
于是所有条目 id 都变成 `206`，`ForEach` 的 key 全部重复，
三列网格直接退化成单列（一个卡片占满整行）。
改成「只看路径 + 取最长的一段数字」，并补了 8 条回归（`tools/engine-test/idcheck.ts`）。

**2. 封面防盗链策略是相反的，必须双向兼容。**
松子漫画的 CDN 不带 Referer 直接 403；云北用的 `oss.mkzcdn.com` 反而是
带外站 Referer 就 403、不带才给。`ImageLoader` 现在先带 Referer 请求，
失败再用空 Referer 重试一次，两种站点都能出图。

## 复用提示

新增图源时按这个顺序验证，能省很多时间：

1. `curl` 首页 → 有没有搜索表单（`<form action>` + `name="keyword|key|q"`）
2. **换两个差异极大的关键词**各搜一次，比对结果集是否不同
   —— 只搜一个词会把「热门推荐」当成搜索成功（松子漫画就踩过）
3. 拿结果页第一条进详情，数章节链接
4. 进第一章，数 `<img>` 里的图片地址；数为 0 就再搜一遍原始 HTML 里的裸图片地址，
   区分「图在 JS 里」和「根本没有图」

# 第二轮补源（2026-11-01 晚）

上一轮把「正文图走页面 JS」的站点一律判为不可用。这一轮换了思路：
**先看图片地址能不能在 HTML 里算出来，算不出来再交给无头取图。**

## 新接入两个源

### 顶漫画 dingmanhua.com ✅ 纯 HTTP

搜索 `/search?query={kw}`（`.manga-card`）→ 详情 `/comic/{id}.html` → 章节 `/chapter/{id}-{cid}.html`。

关键在章节页内联脚本：

```js
var num =eval("45")
var pasd = "https://image1.dingmanhua.com/mh/{hash}/{uuid}/"
for (let i = 1; i <= num; i++) img.dataset.src = pasd + i + '.webp'
```

页面里只有一张懒加载占位图，但**前缀和数量都是明文**，图片地址完全可算。
为此给引擎加了 `images.type = "sequence"`：

```json
"images": {
  "type": "sequence",
  "pattern": "var pasd = \"([^\"]+)\"",
  "countPattern": "var num =eval\\(\"(\\d+)\"\\)",
  "template": "{base}{i}.webp"
}
```

**目录**：详情页 HTML 只内嵌最近 24 章（站点用「加载更多」按钮补），
完整目录来自 `POST /comic/{comicId}`，body 为 `{}`，返回 `data.chapters`：

```json
"chapters": {
  "json": {
    "source": "remote", "url": "/comic/{comicId}", "method": "post", "body": "{}",
    "path": "$.data.chapters", "idField": "id", "titleField": "chapterName",
    "linkTemplate": "/chapter/{contentId}-{id}.html"
  },
  "reverse": true
}
```

接口只给 `contentId` 和 `id`、不给地址，所以又补了 `linkTemplate`
（花括号里写 JSON 字段名）。火影忍者：HTML 24 章 → JSON 83 章。

> 交叉验证：Legado 源合集里有一条顶漫画源，用的正是同一套
> `num`/`pasd` 正则 + `java.postJson('/comic/'+cid,'{}')`，
> 它还额外做了 image1/image2 双 CDN 交替 —— 实测两边字节完全一致，
> 不交替也能全量取到。

### 云漫画 yunmanhua.com ⚠️ 无头取图

- 搜索 `/index.php/search?key={kw}`（首页搜索框挂在 `main.js` 的 `doSearch()` 里，
  不在 `<form>` 上，所以上一轮误判成「没有搜索入口」）
- 详情 `/62kD4weNke`（8 位短码），章节 `.chapter-list .list a`
- 正文：mccms 的 `params = '…'` 是一段 AES 密文，页面用 `crypto-js` 解出
  `{host, source_id, images:[...]}` 再渲染 —— 纯 HTTP 拿不到
  → `images.type = "web"`，`readySelector: "img[data-read-src]"`，
  `extract: "attr:data-read-src"`（渲染后 `src` 是 `blob:`，只有 `data-read-src` 是真地址）

火影忍者：搜索 6 条、详情 456 章。

## 顺带修掉的一个显示级 bug

书架「继续阅读」点进去直接报 `云北漫画：HTTP 404`：
`ReadProgress` 只存了 `comicId`，没存详情页地址，阅读器只能用
`baseUrl + '/' + comicId` 兜底，而各站详情路径差异极大
（云北 `/index.php/comic/{slug}`、206 `/comic_{id}.html`）。

修法：进度记录增加一列 `url`（第 10 列，老记录缺列时留空，向下兼容）；
阅读器启动时按「参数 → 进度 → 书架/收藏 → 用书名回源站搜一次」四级兜底找地址。
