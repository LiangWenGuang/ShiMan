`tools/probe-search2.mjs`（候选搜索地址矩阵），原始结果分别在

## 新接入的两个源

### 云北漫画（mhw1.com）

包子漫画的镜像站，同一个 CDN（`s1.bzcdn.net`）。

- 搜索 `/search?key={kw}`，条目 `.comic-list-item`
- 详情 `/index.php/comic/{slug}`，标题 `h1.comic-name`，封面在 `.box-back` 的
  `background-image` 里（用正则后处理抠出来），简介 `.comic-intro`
- 章节 `.catalog-list li.chapter-item a`，**倒序**，需 `reverse: true`
- 正文 `ul.comic-list li.comic-page img`，36 张
- 分类：首页 `.comic-item-jp`

### 206漫画（m206.com）

- 搜索 `/search?key={kw}`，条目 `.comic-list .comic-item`，标题优先取 `h3 a@title`
- 详情 `/comic_{id}.html`，标题 `.comic-main-info h1`，封面 `.comic-cover-large img`
- 章节 `.chapter-list .chapter-item a`，正序
- 正文 `.comic-content img`，35 张
- 分类：`/custom/new`、`/custom/top`（容器是 `.comic-item`）、`/category/`

## 探测过程中修掉的两个通用 bug

**1. `comicId` 抽取被域名数字污染。**
`extractNumericId` 原来取整串 URL 里第一段数字，而 206 的域名是 `m206.com`，
于是所有条目 id 都变成 `206`，`ForEach` 的 key 全部重复，
三列网格直接退化成单列（一个卡片占满整行）。
改成「只看路径 + 取最长的一段数字」，并补了 8 条回归（`tools/engine-test/idcheck.ts`）。

**2. 封面防盗链策略是相反的，必须双向兼容。**
松子漫画的 CDN 不带 Referer 直接 403；云北用的 `oss.mkzcdn.com` 反而是
带外站 Referer 就 403、不带才给。`ImageLoader` 现在先带 Referer 请求，
失败再用空 Referer 重试一次，两种站点都能出图。

## 复用提示

新增图源时按这个顺序验证，能省很多时间：

1. `curl` 首页 → 有没有搜索表单（`<form action>` + `name="keyword|key|q"`）
2. **换两个差异极大的关键词**各搜一次，比对结果集是否不同
   —— 只搜一个词会把「热门推荐」当成搜索成功（松子漫画就踩过）
3. 拿结果页第一条进详情，数章节链接
4. 进第一章，数 `<img>` 里的图片地址；数为 0 就再搜一遍原始 HTML 里的裸图片地址，
   区分「图在 JS 里」和「根本没有图」
